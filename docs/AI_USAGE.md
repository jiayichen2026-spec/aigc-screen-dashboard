- 工具：Codex；Vercel 部署技能与连接器；GitHub；浏览器验证工具。
- 用户实际要求：已创建 GitHub 仓库并连接授权 Vercel，要求完成第三步骤（创建项目并首次部署），有具体问题时提供选项。
- 输入背景：此前确定 React、TypeScript、Vite、ECharts、JSON 模拟数据与 Vercel 静态部署路线，目标为 AIGC 互动大屏运营后台。
- AI 完成：基础页面、响应式布局、空状态、指标口径对话框、筛选控件状态、构建配置、运行说明与部署验证。
- 人工决策：候选人选定第三题、确认部署路线、创建仓库和授权账号。
- 后续由候选人据实补充：亲自审核或修改的交互、指标定义、数据规则和验收结果。不得将 AI 实现写为本人手写代码。

当前尚未生成模拟业务明细，亦未实现最终统计和异常详情。页面数值显示“—”，不代表真实运营结果。

## 第四步：可复现模拟数据与异常案例

- 用户实际要求：制作可复现的模拟数据及异常案例；若与现有架构冲突，先报告，不修改冲突源代码。
- 兼容性核对：沿用 `src/data/catalog.ts` 中的四个点位ID和六类指标口径，使用静态JSON文件；未修改已有 `src/` 文件、依赖或部署配置。
- AI完成：固定随机种子的Node.js生成器、明细JSON、9个案例定义、SHA-256清单、数据校验器、18项测试和数据字典。
- 数据生成方法：正常流量为确定性伪随机样本；异常时窗显式注入超时、耗时升高、低扫码和审核问题。均为教学与展示数据，不代表行业基准或真实统计结论。
- 验证方法：跨UTC、北京时间、纽约时间的独立进程逐字节复现；不同种子；手工可算小样本；篡改字段与文件的反例测试。
- 范围：本步只交付数据层，未将数值接入现有页面。候选人后续自行补充审核、选择或调整过的数据规则。

## 第五步：独立指标计算逻辑

- 用户实际要求：编写指标计算逻辑，为页面接入做准备；若与现有架构冲突，先报告，不修改冲突源代码。
- 兼容性：保持原有JSON、生成器、React组件、catalog中的指标定义与部署配置不变；新增纯TypeScript计算模块和数据类型，不引入运行依赖。
- AI完成：按北京时间归属的日期与点位筛选、六类指标汇总、每日趋势、点位比较、设备快照、null显示格式及可追溯明细ID。
- 验证：与第四步独立QA逐字段比较、150种日期和点位组合、手工样本、跨午夜和不同时区、零分母、数据损坏反例、调用方数据不可变性。
- 新增展示辅助信息：区分无记录与日期未覆盖，标记快照当天未结束；不改变六项指标公式。
- 范围：未把结果接入页面，也未实现异常详情或自动告警。候选人的后续审核与手动修改应据实补充。
