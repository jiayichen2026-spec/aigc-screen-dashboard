# 第七步：异常中心

以已有 `public/mock/scenarios.json` 的9个案例为规则配置，从会话、生成任务和设备明细重算观察结果。不使用 `scenario_ids` 标签决定是否异常，不更改指标口径和数据文件。

## 页面能力

- 列表：统计窗口／快照、点位、关注项类型、观察结果和触发阈值。
- 筛选：沿用顶部日期、点位；另可选择“全部关注项／异常／数据提示”。默认7天7项，30天9项。
- 详情：分子分母、关联范围、可能原因、建议行动。每页10条任务明细，可展开内部尝试、失败代码、审核、结果展示和扫码事件。
- 设备：设备ID、最后心跳、快照判断；不推断受影响用户或确认故障时长。
- 定位：从详情返回该点位和日期的概览；设备只定位点位，保留现有业务日期。
- 加载：案例文件独立加载、15秒超时和重试。案例读取失败时不清空概览指标。

## 日期和规则语义

业务只检查配置内的案例窗口，计算窗口为案例日期与当前筛选日期的交集。改变日期可能使样本量不足或阈值不再满足，案例会从列表移除。列表明确显示实际计算窗口，不能把此窗口的数值当成整个所选30天的表现。

设备案例不受业务日期影响，因此在没有业务日期覆盖时仍可能展示设备离线或未知。未知属于数据提示。空体验和3次体验案例也属于数据提示，不等同于业务故障。

比例规则先检查最小分母，再判断未经舍入的真实比值。零分母不当作0触发低比例异常。无触发仅表示当前配置、筛选和类型下未满足规则，不代表系统绝无异常。

根因均为未确认。此版本不是实时通用告警系统，也未实现工单、确认/关闭状态、通知或历史心跳趋势。没有虚构“已处理”按钮。

## 默认完整案例窗口的结果

| 案例                  | 观察值        | 演示条件                 | 关联明细                             |
| --------------------- | ------------- | ------------------------ | ------------------------------------ |
| 上海10月2–3日生成失败 | 21/62＝33.87% | ≥25%，至少30个已结束任务 | 失败任务，含具体错误代码             |
| 杭州10月3日生成耗时   | 60.35秒       | ≥35秒，至少10个成功任务  | 所有参与均值的成功任务，并非逐条超时 |
| 北京10月1–3日扫码转化 | 3.19%         | <15%，至少30个可领取会话 | 已展示但尚未扫码的会话               |
| 成都10月2–3日审核拦截 | 34.43%        | ≥20%，至少20个已审核结果 | 被拦截任务及审核原因                 |
| 杭州10月4日审核积压   | 20个          | 待审核≥3                 | 待审核任务及截至快照的等待时长       |
| 成都02设备            | 离线          | 心跳超过5分钟            | 设备最后心跳                         |
| 北京02设备            | 未知          | 缺失心跳                 | 不能归类为离线                       |
| 成都9月5日            | 0次体验       | 体验数＝0                | 无明细，不推断设备故障               |
| 北京9月5日            | 3次体验       | 体验数＝3                | 三条体验，提示谨慎比较               |

“上海生成超时增多”沿用模拟案例标题，触发指标实际是生成失败率。具体失败原因由每条任务的failure_code验证，不将所有失败一概称为超时。

关联去重用户数仅表示关联证据中出现的用户，不代表确认受损人数。同一体验可关联多个关注项，数量不可直接加总。

## 文件与测试

- `src/lib/exceptions.ts`：规则校验、交集窗口、样本门槛、观察结果与证据关联。
- `src/lib/exception-display.ts`：指标、规则、证据与错误代码文案。
- `src/lib/load-exceptions.ts`、`src/hooks/useExceptions.ts`：独立请求、取消、错误与重试。
- `src/components/ExceptionCenter.tsx`：筛选、列表、模态详情、证据分页和概览定位。
- `tests/exceptions.test.mjs`：17项测试，包含与第四步独立QA对照、不依赖标签、阈值边界、零分母、样本不足、设备日期独立、错误配置、输出修改隔离及加载失败。

`npm test`共64项；`npm run build`执行类型检查和生产构建。原ECharts包体积提示仍在，不影响构建。

## 建议演示顺序

1. 默认7天，向下到异常中心，打开“上海生成超时增多”。
2. 展示21/62的分子分母、原因待确认与建议行动，展开一条任务查看超时和尝试记录。
3. 点击“在概览中查看此范围”，核对上海10月2–3日成功率66.13%与失败率互补。
4. 重置后查看北京02设备未知，说明未知与离线的区别。
5. 切换30天查看成都9月5日空体验案例，展示无记录不会误判为故障。
