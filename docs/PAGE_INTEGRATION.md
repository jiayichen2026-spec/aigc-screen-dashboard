# 第六步：页面数据接入

本阶段完成数据到页面的连接，不改变既有指标公式、数据文件或静态托管架构。无需数据库、模型API、环境变量或新增依赖。

## 数据流

页面初始化 → 并行读取 `/mock/metadata.json`、`sessions.json`、`generations.json`、`devices.json` → 检查HTTP、JSON和数据契约 → 创建一次指标计算器 → 根据日期和点位计算 → 更新卡片、趋势、点位比较、审核和设备。

- `src/lib/load-dashboard.ts`：并行请求与计算器构建。HTML托管回退、HTTP错误、损坏数据会拒绝，不会变成全零。
- `src/hooks/useDashboardData.ts`：加载状态、15秒超时、卸载取消和重试；旧请求不会更新已经卸载的组件。
- `src/App.tsx`：保存筛选状态，通过同一结果驱动业务展示。自定义日期需点击“应用日期”，无效区间保留上次有效结果。
- `src/components/TrendChart.tsx`：两条曲线使用独立坐标轴，缺失值断开，数字只在展示时舍入；每日表格供精确查看与辅助技术访问。
- `src/components/DeviceList.tsx`：独立快照时间、设备心跳和在线/离线/未知状态。

## 交互与边界

1. 默认最近7天，时间锚定2026-10-04模拟快照。30天从2026-09-05开始。
2. 自定义日期可包含数据覆盖以外日期，界面明确提示；最多366天。
3. 点位筛选联动全部业务模块；设备只随点位变化，不随业务日期变化。
4. 参与人数为筛选范围内重新去重，不能加总各日或各点位人数来替代。
5. 待审核、失败、排队、处理中分别展示；处理中不计为失败。
6. 空记录：人数0，比例和耗时“—”。未覆盖：所有业务值“—”，设备快照仍显示。
7. 当日不完整和少于30次体验的样本提示用于解读，不作为自动异常判定规则。
8. 加载失败时筛选暂停，指标“—”，可点击“重新加载”。

原生日期框在浏览器自动化工具中不能稳定用文本fill操作；边界日期验证使用原生value setter及input/change事件，再点击真实“应用日期”按钮。没有修改页面以绕过日期校验。

本地加载四类数据最终HTTP均为200；React开发模式首次试运行的请求可因StrictMode清理而取消，这是预期行为。生产模式不重复执行该开发检查。模拟网络失败会产生预期网络日志；正常路径没有未捕获脚本错误。
